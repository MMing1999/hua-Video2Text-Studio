# 二次开发功能规划

> 基于 bili2text 本地部署的扩展方向（2026-11-26）
> 当前基线：v0.4.1，引擎默认 Whisper，Web 入口 `http://127.0.0.1:8765`

## 总览

| 序号 | 方向 | 目标 | 优先级建议 |
|------|------|------|------------|
| 1 | 前端页面优化 | 更好用、更清晰的 Web 操作体验 | 高（先改善日常使用） |
| 2 | 补充各种来源视频 | 不只 B 站，更多平台/链接可直接转写 | 高（扩大使用场景） |
| 3 | 文稿排版和优化整理 | 转写结果可读、可导出、可再加工 | 中高（提升结果价值） |

## 2. 补充各种来源的视频

### 想解决什么
现在在线来源基本只认 B 站 BV/链接；本地音视频已支持。希望扩展到更多平台。

### 现状（2026-11-26）
- ✅ 本地文件：mp4 / mkv / mov / mp3 / wav 等
- ✅ B 站：BV 号、视频链接、分 P
- ✅ YouTube、AcFun（A 站）
- ✅ X / Instagram / Facebook（公开可试；登录墙需 Cookie）
- 🧪 抖音 / 小红书：已接入，标为实验性（风控易变）
- ❌ Telegram 等：未开放，建议本地文件路径

### 可能包含（后续）
- 更多站点 / generic URL
- Cookie UI 深化、代理可视化、失败重试
- 批量任务里混用多来源的体验打磨

### 相关代码
- `src/b2t/inputs.py`（来源解析）
- `src/b2t/downloaders/`（下载实现）
- `src/b2t/factory.py` / `pipeline.py`

### 风险
部分平台受 yt-dlp 上游能力与风控影响（如抖音），需按平台验收，不宜一次承诺「全网」。

## 3. 文稿排版和优化整理

### 想解决什么
原始转写往往是一大段口语文本，阅读和二次使用成本高。

### 可能包含
- 自动分段、加标题、去口头禅/重复
- 说话人区分（若可行）
- 生成摘要 / 要点 / 大纲
- 导出 Markdown、SRT/VTT 字幕、纯文本、Notion 等
- 在 Web 里直接预览编辑后的排版结果

### 相关代码
- `src/b2t/library.py`（原文 / 编辑版版本管理）
- `.b2t/transcripts/original/`、`.b2t/transcripts/edited/`
- Web 结果展示与保存流程

### 状态（2026-11-26）
Studio 已接入 **AI 纠错 / AI 排版**（`POST /api/ai/transform`），配置在 `.b2t/config.json` 的 `ai` 字段；需安装 `openai`（可用 `uv sync --extra mimo`）。摘要与跨平台迁移仍待做。

### 备注
「整理优化」可先做规则型排版，再考虑接大模型做摘要与润色（需额外 API Key）。
